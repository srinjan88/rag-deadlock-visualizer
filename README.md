Resource Allocation Graph (RAG) Deadlock Visualizer & DetectorAn interactive, full-stack web application for building, visualizing, and evaluating Resource Allocation Graphs (RAG) to detect deadlocks in multi-programming operating systems. Built for educational demonstrations and academic evaluations, this simulator bridges theoretical OS concepts with real-time graph visualization and algorithmic trace logging.Key FeaturesDual-Engine Algorithmic Analysis:Single-Instance Resources: Executes Depth-First Search (DFS) Cycle Detection on directed process-resource dependencies ($O(V + E)$).Multi-Instance Resources: Executes the Graph Reduction Algorithm using matrix evaluation to simulate unblocked process execution and resource release ($O(m \times n^2)$).Interactive Vis.js Network Canvas:Custom node representations: Process nodes (Circles) and Resource nodes (Rectangles with instance capacities).Explicit edge directions: Request edges ($P \rightarrow R$, dashed arrows) and Allocation/Assignment edges ($R \rightarrow P$, solid arrows).Real-time drag, drop, and node color highlighting (Red for deadlocked state, Green for safe/reduced state).Real-Time System Matrices ($A, Q, V$):Automatically calculates and displays the Allocation Matrix ($A$), Request Matrix ($Q$), and Available Vector ($V$) as graph edges are drawn.Over-Allocation Validation Guard:Backend physical validation that catches impossible system configurations (e.g., assignment edges exceeding declared resource capacity) and raises 400 Bad Request state errors.Pre-loaded OS Textbook Scenarios:Preset 1: Single-Instance Deadlock Cycle (Circular wait state).Preset 2: Safe Allocation State (Sequential process reduction).Preset 3: Multi-Instance Graph Reduction (Cycle present, NO deadlock).Execution Trace Console:Side panel detailing step-by-step reduction paths, cycle traversals, and system status logs for OS viva evaluations.Tech StackBackend: Python 3.8+, Flask 3.x, GunicornFrontend: HTML5, CSS3, Tailwind CSS (via CDN)Visualization Library: Vis.js Network (via CDN)Deployment: Production-ready for Render, Heroku, or GitHub PagesProject StructurePlaintextOS RAG/

Single-Instance Mode (DFS Cycle Detection)When all resources in the graph have a capacity of 1 ($R_j = 1$), a cycle is both a necessary and sufficient condition for a deadlock.The algorithm constructs an adjacency list from request ($P \rightarrow R$) and allocation ($R \rightarrow P$) edges.Depth-First Search with a recursion stack set traces active dependency paths.If a node in the current recursion stack is revisited, a directed cycle is flagged, and participating processes/resources are marked deadlocked.2. Multi-Instance Mode (Graph Reduction Algorithm)When resources have capacities greater than 1 ($R_j > 1$), a cycle does not necessarily imply a deadlock.Allocation Matrix ($A_{i,j}$): Count of allocation edges $R_j \rightarrow P_i$.Request Matrix ($Q_{i,j}$): Count of request edges $P_i \rightarrow R_j$.Available Vector ($V_j$): $\text{Capacity}(R_j) - \sum_{i} A_{i,j}$.Reduction Steps:Find an unreduced process $P_i$ where $Q_{i,j} \le V_j$ for all $j$.If found, simulate process completion: $V_j = V_j + A_{i,j}$ and mark $P_i$ as reduced/finished.Repeat until no further processes can be reduced.Any process remaining unreduced indicates a deadlocked state.Deployment InstructionsDeploying on RenderSign in to Render.com and link your GitHub repository.Click New + $\rightarrow$ Web Service.Set the following environment configurations:Runtime: Python 3Build Command: pip install -r requirements.txtStart Command: gunicorn app:appClick Create Web Service.Author & Course CreditsCourse: 21CSC202J – Operating SystemsInstitution: SRM Institute of Science and TechnologyDeveloper: Srinjan Sengupta
